## Review of PRs #23-#26 (diff 0364f7d..6338f2c)

Code-review and security-review pass over `dependency-gate.py`, `build.py`, `cli.py`, `uv.toml`, `pyproject.toml`, `uv.lock`. No CRITICAL, HIGH or MEDIUM findings. The gate changes are a net hardening relative to v1.18.3. No new network endpoints beyond `pypi.org` and `registry.npmjs.org`, no subprocess or eval, TLS verification never disabled. `build.py` change is template text only; no build-time code execution added. Every locked version in `6338f2c:uv.lock` predates its `exclude-newer` cutoff except certifi (covered by the now-retired exception).

LOW findings (not fixed in this release):

1. `dependency-gate.py` `evaluate_license`: parentheses are flattened before splitting on `OR`, so `(MIT OR GPL-3.0) AND LGPL-3.0` evaluates as allowed. Still strictly tighter than the v1.18.3 substring match.
2. `dependency-gate.py` `_parse_npm_spec`: non-registry npm specs (`github:user/repo`, `user/repo`, `npm:` aliases) are dropped without a stderr reminder; v1.18.3 printed a manual-check notice for every npm token. URL/VCS/path specs were already skipped for both ecosystems before this change.
3. `dependency-gate.py` `check_npm`: semver ranges are checked against the `latest` dist-tag, which may differ from the version npm resolves. Parity with `check_pypi`.
4. `dependency-gate.py` `_pypi_license`: multiple license classifiers are joined with `OR`, so one permissive classifier admits the package.
5. Test coverage of `dependency-gate.py` is 74%; `main()` (lines ~697-752) has no end-to-end test.
6. `uv` warns that `[tool.uv] constraint-dependencies` is ignored because `uv.toml` exists. Empirically the constraints are applied (recorded in `uv.lock [manifest]`, and the new filelock floor forced the upgrade), but the warning is misleading; consolidating config into one file is a follow-up.
